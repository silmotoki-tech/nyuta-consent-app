# 設計判断ログ

「なぜその設計にしたか」を記録する。実装のコミットには何を変えたかは残るが、検討した
代替案や却下した理由までは残らないため、ここに書く。特にこのアプリは今、v1（React +
Firebase + PDF生成）から内容・デザイン・技術構成すべてを作り直す途中で、実装より先に
仕様を固める方針をとっている。実装が始まる前にここへ書き残す意味が大きい。

新しい判断を追記するときは、日付・決めたこと・理由・検討した代替案（あれば）の順で書く。

---

## 2026-08 v1の実装と、そこで見えた限界

v1は React + Vite + Tailwind + Firebase（Firestore + Storage、メール/パスワード認証の
院内共通アカウント）で構築。`html2pdf.js` / `html2canvas` でA4のPDFを生成し、印刷と
Firebaseへの月別保存を行う構成だった（もともとGeminiでVSCode実装していたが、デザインが
安定せずClaude+Cursorに引き継いで作り直した経緯がある）。

**見えてきた限界**:
- A4 1ページに収めたい書類が複数ページに膨れる、デザインが安定しない
- PDF出力の精度に不満が残る（枠内に文字が収まらない、丸数字バッジのずれ等）
- `html2pdf.js`の保存失敗バグ（`(0 , X.default) is not a function`）が3回の修正試行でも
  根本解消せず、`trim-canvas`のESM/CJS interop起因と分かってからも回避策止まりだった
  （詳細は `docs/bugs.md`）
- 文字の羅列になり、紙の書類が持っていた分かりやすさを失っていた

**結論**: PDF生成という技術方式自体がこのアプリの目的（その場で分かりやすく説明し、
署名してもらう）と相性が悪いと判断し、内容・デザイン・技術構成をすべてゼロから
作り直す方針に決定。

## 2026-09 v2: 紙芝居形式への全面転換

**決定**: 全書類を「1枚ずつめくって説明する」紙芝居形式に統一する。注意事項の列挙も
1画面に詰め込むと見にくいため、同じ形式に統一する。

**理由**: v1で分かったのは、A4 1枚に収める・PDFで出すという制約が先にあったために
内容の見せ方が窮屈になっていたこと。説明の場での分かりやすさを主目的に置き直し、
「見せる場面」と「渡す書類」を分けて設計する。

### PDF生成ライブラリの廃止

**決定**: `jsPDF`等のPDF生成ライブラリ、日本語フォントの組み込みを一切使わない。
印刷はA4レイアウトのHTMLをブラウザの`window.print`で出す形にする。

**理由**: v1の不具合の大半がPDF生成ライブラリ起因だったため、その技術要素自体を
なくすのが最も確実な解決策と判断。1枚に収まらない書類は文字を小さくして対応する。

### スライドの作り方・登録方式

**決定**: スライドはGoogleスライド等で作成し、書き出したもの（PNG画像、1スライド＝
1枚）をアプリに登録する。登録時点でバージョン固定し、編集中の原本を直接参照しない。
既存バージョンの編集・削除は誰にもできない構造にする（機能を作らない＋Firebase
Storageルールで既存ファイルへの書き込みを拒否）。

**理由**: PNG画像方式はPDF描画ライブラリへの依存を持ち込まないための選択。バージョン
固定・改変不可にするのは、後述の証明力の担保のため。

**却下した代替案**: ハッシュ値の外部記録などの厳格な改ざん対策は過剰と判断。飼い主も
控えを持つため、両者を突き合わせれば改ざんが判明する構造自体が実効的な担保になると
整理した。

### スライド登録機能はアプリに作らない

**決定**: スライドの登録・改訂はタモやんが全て手元で行うため、アプリ側に登録機能は
作らない。当初検討していた院長・副院長のみのパスコード保護も、この決定により不要に
なった。アプリはスライドを読み込んで表示するだけの役割。

### スライドの原稿づくり

**決定**: スライドは現行書類の文字起こしを元にAIで作成する。ただし飼い主に渡す
プリントアウト用の書類は、文字起こしの原文をそのまま使い体裁だけ整える（AIによる
要約・言い換えはしない）。書類は一度に全部ではなく順に作る。優先順位は使用頻度の
高い一般手術注意事項→検査注意事項→麻酔のおはなしの順。

**理由**: 渡す書類は証拠性が求められるため、原文を保つ必要がある。スライドは説明用
なので、分かりやすさを優先してAIで整えてよいという整理。

## 2026-09 対象書類の絞り込み（12種類→10種類）

**決定**: ペットホテル承諾書・入院預かり承諾書の2種は今まで通り紙で運用し、アプリの
対象から外す。よって対象は10種類（手術説明5種・麻酔関連2種・予約注意事項3種）。

**理由**: この2書類だけ住所・電話番号を書いてもらう欄があり、他の書類にはない個人情報
入力が絡む。対象を絞ることで、アプリ全体の入力項目をシンプルに保てる。

## 2026-09 画面フロー

**決定**: スタート画面（患者情報・書類選択などをスタッフが登録）→確認画面（入力値の
表紙的な確認、名前の取り違えに気づける安全確認を兼ねる）→紙芝居（飼い主が理解チェック
しながら閲覧）→蘇生処置の選択（該当書類のみ、署名の直前に独立した1枚として配置）→
署名画面（電話番号・緊急連絡先＋署名）→最終確認画面（説明者・予定表記入者の選択、
予定表記入チェック。署名後にiPadを返してもらってからスタッフが操作）→出力、の順。

スタート画面で複数の書類を選べるようにし、選んだ順にこのフローを書類ごとに繰り返す。
患者情報の入力は最初の1回だけ。中断状態の保存はせず、別日に続きをやる場合は最初から
やり直す（済んだ分の書類は書類ごとに都度保存・印刷されるため残る）。

**理由（確認画面）**: スライド画像に日付や名前を差し込む仕組みは作らない方針にしたため
（位置合わせの調整が必要でエラーが起きやすい）。入力値が必要な情報は確認画面と渡す
書類（どちらもアプリが生成する側）で表示し、スライド自体は内容が固定のものだけにする。

**理由（未チェックでも進める）**: 想定ページ数は最大3〜4ページ程度なので、未チェック
項目へのジャンプ機能は不要と判断（戻るで足りる）。ただし全チェックが揃わないと署名は
できない仕様にする。

**理由（蘇生処置を署名直前の独立ページに）**: 命に関わる重要事項のため、他の注意事項と
まとめず単独で意思確認する。

## 2026-09 出力とデータ保存の方針

**決定**: 出力は2種類。飼い主に渡すのはA4 1枚（スライドの内容を省略せず全文を小さめ
フォントで収めたテキスト書類＋署名）。病院の控えにはスライド一式＋署名・チェック記録を
保存する。渡す1枚の文章とスライドの文章は目的が違うため別々に作成する。

控えはPDFの実体としては保存せず、「署名画像＋入力内容＋チェック記録＋スライドの
バージョン＋印刷日時」というデータのみを保存する方針に変更した。スライド本体は
バージョンごとに1セットだけ保存し、各署名記録は「どのバージョンを見せたか」の参照のみ
持つ（重複保存を避け容量を節約）。見返しや紙が必要なときは、保存済み記録を開いて
印刷する機能を必須とする。印刷操作をした日時は記録に残し、再発行も含め複数回分を
履歴として保持する。

**理由**: PDF生成ライブラリと日本語フォント組み込みが不要になり、v1で苦しんだ部分を
丸ごと排除できるため。証拠性はスライドのバージョン固定＋追記のみの改訂ルールで担保する。

### 証明力についての整理

iPadの指サインは筆跡鑑定に耐えないが、各ページの理解チェック時刻・スライドの
バージョン・説明者・印刷日時といった過程の記録が残るため、署名だけの紙より証明力は
高いという整理をしている。「控えをもらっていない」と主張された場合の備えとして印刷
日時を記録するが、紙の運用でも渡した証拠は残らないので状況は同じ、という前提も
併せて整理済み。

## 2026-09-10 v2実装キックオフ（一般手術注意事項）

**決定**: 最初の1書類として一般手術注意事項を紙芝居フローで実装する。v1の
`ConsentForm.jsx` / `html2pdf.js` には触れず、入力画面は v2 フローに切り替える。

**決定**: カルテ番号はスタート画面に置かない。v1後期で欄を廃止した判断を踏襲する。

**決定**: スタッフ名は `src/v2/staff.js` に配列で直書きする。院内メンバーが少人数で
固定のため。マスタ管理は別issue。

**決定**: スライド画像は ID（`ippan_shujutsu_01` など）とファイル（`01.png`）を分離し、
内容差し替え時はファイルだけ入れ替える。今回のPNGは仮素材（スライド2には「食べたものを
吐いてしまうと危険なため」を入れておく）。

**決定**: Firestore は既存の `consents` コレクションに `schemaVersion: 2` で保存する。
既存の認証ルールをそのまま使える。控えの実体は確認記録画像（署名＋チェック時刻＋説明者）
を Storage の `consents/` 配下に置く。

**決定**: 渡す書類の印刷は HTML を別ウィンドウに書いて `window.print()` する。PDF
ライブラリは使わない。
