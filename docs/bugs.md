# 不具合・課題ログ

v1（PDF生成方式）で見つかった不具合と、その対応・教訓を記録する。v2はPDF生成
ライブラリ自体を廃止する方針のため、これらの多くはv2では再発しない設計上の理由に
なっている（`docs/decisions.md`参照）。

## v1で解決した不具合

- **`trim-canvas`のESM/CJS interopによる保存失敗**（`(0 , X.default) is not a function`）:
  `react-signature-canvas`が署名のトリミングに使う`trim-canvas`は、mainがwebpack UMD
  形式のminifiedファイルのため、Vite/RollupのCJS interopで`default`が二重にラップ
  されてしまい発生。`vite.config.js`で素のESMソース（`trim-canvas/index.es6`）に
  直接エイリアスして回避（このエイリアスを外すと再発するため要注意、と`README.md`に
  明記済み）。3回の修正試行を要した
  - 関連コミット: `c8a4523`（html2canvasを先に解決）, `5b97dae`（html2canvas-shim.jsで
    読み込み順序を保証）, `ce50df4`（最終的な修正）
- **iPad Safariで保存は成功するのに印刷ウィンドウが開かない**: `5c6fa95`で修正
- **印刷ウィンドウでPDFの印刷が実行されない**: `28c4c27`で修正。最終的に印刷は
  手動2ステップ（PDF表示→共有アイコンからプリント）を正式な流れとして確定（`b1c9688`）
- **html2canvasでの入力欄文字クリップ・丸数字とチェックマークのズレ**: `dfe3ded`で修正

## v1で解決せず、方式転換の理由になった不満

- A4 1ページに収めたい書類が複数ページに膨れる
- デザインが安定しない
- PDF出力の精度（枠内に文字が収まらない、丸数字バッジのずれ等）に不満が残った

これらは個別修正を重ねても再発・類似の不具合が続いたため、「PDF生成という技術方式
自体を廃止する」という v2 の方針決定に至った。

## v2 の積み残し

- スタッフ名は役職の仮リスト。正式名への差し替えが必要
- スライドPNGは仮素材。Googleスライド書き出しへの差し替え前提
- 複数書類の連続処理は未実装
